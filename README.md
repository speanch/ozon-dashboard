# Ozon Dashboard

Аналитический дашборд для продавца на маркетплейсе Ozon: заказы, динамика продаж,
рекламные кампании, бустинг и эксперименты — в одном интерфейсе, с данными из
нескольких кабинетов продавца.

Проект построен вокруг реального мебельного бизнеса (данные обезличены) и покрыт
синтетическими демо-данными, поэтому запускается без доступа к API.

## Как устроено

```
Ozon Seller API ──────┐
Ozon Performance API ─┤→ ETL-пайплайн (run_etl.py) → SQLite → Streamlit (dashboard.py)
                      ┘
```

- **ETL-пайплайн** выгружает заказы, аналитику, остатки, финансы, цены, рекламную
  статистику и бустинг из двух API Ozon. Клиенты API умеют троттлинг (лимиты
  Ozon — 2 запроса/сек), повторные попытки с backoff при 429 и инкрементальную
  догрузку по состоянию последней синхронизации (`EtlState`).
- **Дашборд** работает только с локальной SQLite-базой — страницы не ходят
  в API, поэтому открываются мгновенно и не зависят от доступности Ozon.

## Стек

Python · Streamlit · Plotly · pandas · SQLAlchemy · SQLite · requests

## Страницы дашборда

| Страница | Что показывает |
|---|---|
| **Главная** | Сводка по кабинетам: заказы, выручка, прибыль, баланс, реклама, рейтинги |
| **Динамика продаж по кабинетам** | Динамика выручки/прибыли/ДРР с наложением любых метрик, выбором гранулярности (день/неделя/месяц/квартал/год) и метками экспериментов |
| **Динамика продаж по артикулам** | Тепловая карта продаж топ-артикулов за период (отрезки пересчитываются автоматически), дневная динамика артикула с наложением метрик и экспериментов |
| **Бустинг 75%** | Товары в акции «Эластичный бустинг»: группировка по уровню бустинга, расчёт минимальных цен, что можно поднять до 75%, отправка новых цен в API |
| **Стратегия рекламы** | Автоматические вердикты по кампаниям (запустить / тест / не запускать) по ROAS и жёсткому лимиту ДРР, недельные бюджеты, план запуска с ожидаемой выручкой |
| **Ценовой индекс** | Ценовые индексы товаров относительно рынка, распределение по цветам индекса |
| **Эксперименты** | Справочник A/B-экспериментов: периоды, кабинеты, привязка к артикулам |

Ключевая идея страницы «Стратегия рекламы» — решения принимаются по прозрачным
правилам (ROAS ≥ 3 и ДРР не выше лимита, заложенного в себестоимость), и дашборд
показывает руководству цифры за каждым вердиктом.

## Быстрый старт (демо-данные)

```bash
pip install -r requirements.txt
python seed_demo.py          # создаст dashboard.db с синтетическими данными
streamlit run dashboard.py
```

Все товары, кампании и цифры в демо — вымышленные. База пересоздаётся удалением
файла `dashboard.db`.

## Запуск на своих данных

1. Скопируйте `.env.example` в `.env` и заполните ключи Ozon Seller API
   (`OZON_SHOP_*_API_KEY`) и Performance API (`PERFORMANCE_SHOP_*_CLIENT_SECRET`).
2. Настройте кабинеты в `etl/config.py` (`SHOP_DEFS`) и экономические
   коэффициенты в `.env` (`COMMISSION_RATE`, `DRR_RATE`, …).
3. Выгрузите данные и запустите дашборд:

```bash
python run_etl.py --days 60
streamlit run dashboard.py
```

## Структура

```
dashboard.py        — точка входа Streamlit, навигация по страницам
run_etl.py          — запуск ETL (--days, --shops)
seed_demo.py        — генератор синтетических демо-данных
etl/
  ozon_client.py    — клиент Seller API (троттлинг, ретраи, 429 backoff)
  performance_client.py — клиент Performance API (OAuth-токены, автопродление)
  pipeline.py       — инкрементальная выгрузка всех сущностей
  models.py         — SQLAlchemy-модели + авто-миграции колонок
  shared_ui.py      — общие компоненты: фильтры периодов, метки экспериментов
views/              — 7 страниц дашборда
```

## Конфиденциальность

Код выложен как портфолио: все ключи API читаются только из `.env`, реальные
клиентские данные (база, выгрузки, отчёты) в репозиторий не попадают, названия
кабинетов и товаров обезличены.
